# Портфолио Егора — версия для GitHub Pages

Готовая автономная версия сайта: главная и четыре опубликованных кейса. Экспорт обновлён 9 ноября 2026 года из локальной версии портфолио. Сохранены русский и английский языки, фильтры, мобильное меню, резюме, просмотр изображений и GIF. Админки, авторизации и серверной базы здесь нет.

## Загрузить и включить сайт

1. Создай репозиторий на GitHub. Самый простой вариант для Pages — публичный репозиторий.
2. Открой **Add file → Upload files** и загрузи **содержимое этой папки** в корень репозитория. На верхнем уровне должны быть `docs`, `src`, `public`, `scripts`, `package.json`, `package-lock.json` и этот README. Не загружай ZIP как один файл и не добавляй ещё один внешний уровень `portfolio-github`.
3. Сохрани загрузку в ветку `main` кнопкой **Commit changes**.
4. Открой **Settings → Pages**. В разделе **Build and deployment** выбери **Deploy from a branch**, затем ветку **main** и папку **/docs**. Нажми **Save**.
5. После завершения публикации GitHub покажет ссылку на сайт. Обычно это `https://ИМЯ.github.io/ИМЯ-РЕПОЗИТОРИЯ/`; для репозитория `ИМЯ.github.io` — корень этого домена. Название репозитория прописывать в коде не нужно.

GitHub публикует готовое содержимое `docs/`; запускать сборку на GitHub и добавлять секреты не требуется. Файл `docs/.nojekyll` уже включён; при загрузке через браузер не исключай его специально.

Официальная инструкция: https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site

## Что находится в папке

- `docs/` — уже собранный сайт, который публикуется на Pages. Внутри отдельный `index.html` для главной и каждого кейса.
- `src/content/site.ts` — тексты по умолчанию и метаданные главной.
- `src/data/home.json` — экспорт сохранённых настроек из локального редактора главной.
- `src/data/projects.json` — опубликованный контент кейсов, порядок карточек и переводы.
- `src/data/media.json` — соответствие идентификаторов изображений файлам в `public/media/`.
- `src/app/` — компоненты главной, кейсов и галереи.
- `src/styles/` — палитра, оформление и адаптивность.
- `public/` — оригиналы используемых изображений, GIF, иллюстраций, шрифтов и favicon; лицензии шрифтов сохранены.
- `scripts/` — сборка, локальный статический сервер и проверка ссылок.

Не изменяй файлы в `docs/` вручную: при сборке они создаются заново из исходников.

## Локальный запуск и обновление

Нужен Node.js версии **22.13 или новее**. Открой терминал в этой папке:

```sh
npm ci
npm run dev
```

Открой `http://127.0.0.1:4173/`. Для остановки нажми Control+C. Это обычный статический сервер без автоматического обновления: после изменений пересобери сайт и обнови страницу.

Для сборки и проверки:

```sh
npm run typecheck
npm run build
npm test
npm run preview
```

Для проверки адреса с названием репозитория на macOS/Linux:

```sh
SITE_PREFIX=/test-repository PORT=4174 npm run preview
```

Открой `http://127.0.0.1:4174/test-repository/`. На Windows можно использовать обычный запуск без переменных окружения.

После редактирования выполни `npm run build`, затем загрузи обновлённые исходники и **всю папку `docs/`** в GitHub. Удалённые файлы старой сборки следует удалить и в репозитории. Загружать `node_modules/` и `.build/` не нужно.

При добавлении изображения положи файл в `public/media/`, добавь запись в `src/data/media.json` и используй этот идентификатор в кейсе. Для нового кейса добавь документ в `src/data/projects.json`: сборка автоматически создаст его HTML. Поле `slug` задаёт адрес; у существующих проектов оно сохранено, включая `prism-ui kit` с пробелом — ссылка кодируется автоматически.

Эта папка — отдельная копия текущих опубликованных работ. Изменения через админку исходного локального проекта сюда автоматически не переносятся. Черновики и неиспользуемые загрузки в экспорт не включены. Файл резюме пока не добавлен; сохранено текущее сообщение об этом. Встроенное внешнее видео, если его добавить в кейс, требует доступа к соответствующему видеосервису.

Двойной щелчок по HTML (`file://`) не заменяет статический сервер: для JavaScript-модулей используй команды выше или GitHub Pages.
